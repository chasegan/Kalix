- WATER ACCOUNTING & RESOURCE ALLOCATION SYSTEMS!
    - New `[acc.*]` sections declare **accounts** — the ledgers of a water sharing plan — as a simple table of names and sizes. Accounts are pure state; they hold a balance and nothing else.
    - New `[ras.*]` sections define **resource allocation systems**: each is one rule — *on this trigger, do this action, to these account groups*. Triggers are calendar boundaries (`start_water_year(m)`, `start_month`, …) or any authored condition; actions are `set_full`, `set_empty`, `set`, `set_fraction`, `credit`, `debit`, `scale`, and `reduce_to`.
    - **Announced allocation** via `allocate(pct)` and `reset_allocation`: assess the resource with an expression (typically a lookup curve over storage), announce a percentage of entitlement, and let it ride monotonically through the year. Priority tiers and reserves fall out as more `[ras.*]` sections.
    - Water users reference accounts with `accounts = a, b` (ordered — first drawn down first); orders and takes are capped by, and debited from, the balance, so an allocation policy constrains real diversions.
    - Account state is readable in any expression — `acc.<name>.opening_balance`, `.closing_balance`, `.debits`, `.allocation`, `.size`, plus group aggregates — and recordable in `[outputs]`, alongside `ras.<name>.fired` and `.pct`. Every credit, debit, and announcement is an auditable series.
    - Linter and autocomplete understand the new sections and references as you type.
    - Documented in full: [Allocation systems](https://kalixproject.org/docs/allocation-systems/), [`[acc.*]`](https://kalixproject.org/docs/accounts/), and [`[ras.*]`](https://kalixproject.org/docs/ras/).
- **Breaking format changes** — section names now match their reference prefixes, for consistency across the model file:
    - `[inputs]` is renamed to **`[data]`** (references inside were already `data.*`). The file paths and references are unchanged — just rename the section header. Loading an old model reports a clear message telling you what to do.
    - `[constants]` is renamed to **`[const]`**, and the reference prefix `c.` to **`const.`**.
    - `account = name, type, size, wy_month` inline on `unregulated_user` is **removed** — declare accounts in an `[acc.*]` section and reference them with `accounts =`.
- Rainfall weights: a new **Beta-corrected stick-breaking** parameterisation for optimising the weights of a linear-combination rainfall input (`rf_bias` + `rf_d*`). A uniform search of the parameter box is now a uniform search of the weight simplex — no station is statistically favoured by the ordering — and optimisations warm-start from the weights already written in the model.
- KalixIDE: **zip and unzip** files directly from the file-tree context menu.
- KalixIDE: fixed relative CLI binary paths set in Preferences (e.g. `../target/release`) so running a model works from any folder, not only the one the IDE was launched from.
- Docs: new and expanded reference pages for the allocation grammar and the [`[const]`](https://kalixproject.org/docs/constants/) section.
