Build your first model

◷ 20 min|Beginner|5 stepsTutorial files ↗
i

Tutorial 1 of the series. You'll build a single-catchment rainfall-runoff model from scratch, run it, and look at the result.

What you'll build

A daily rainfall-runoff model for the fictional Stringybark Creek catchment — a Sacramento catchment node feeding a downstream gauge node, driven by ~30 years of daily rainfall and PET data. By the end you'll have a working model file, a simulation, and a chart of simulated vs. observed streamflow.

Build the model

We'll build stringybark_sacramento.ini one section at a time.

1The [kalix] section

Top-level model settings. We'll lock the simulation period to the 30 years our data covers.

stringybark_sacramento.inicopy
[kalix]
start = 1980-01-01
end   = 2009-12-31

2The [inputs] section

The data files the model will load. Bare filenames resolve relative to the model file's folder. A single CSV can hold many value columns.

stringybark_sacramento.inicopy
[inputs]
climate_data.csv
observed.csv

3A Sacramento catchment node

The heart of the model. Sacramento takes daily rainfall and PET and produces streamflow at the catchment outlet. The data.<file>_csv.by_name.<column> syntax wires a node input to a named CSV column.

stringybark_sacramento.inicopy
[node.0001_sc_stringybark]
type  = sacramento
loc   = 0, 0
area  = 228
rain  = data.climate_data_csv.by_name.rain_mm
evap  = data.climate_data_csv.by_name.pet_mm
# params = 17 pre-calibrated Sacramento parameters
ds_1  = 0002_ga_widebridge

ds_1 connects this node's first downstream link to the gauge we'll define next.

4A downstream gauge node

A gauge is a passive node — it doesn't modify flow, it just gives you a named point in the network to inspect and record streamflow.

stringybark_sacramento.inicopy
[node.0002_ga_widebridge]
type = gauge
loc  = 0, 40

5The [outputs] section

The results to record — flow at both nodes plus the three Sacramento runoff components (flosf, flobf, floin).

stringybark_sacramento.inicopy
[outputs]
node.0001_sc_stringybark.dsflow
node.0001_sc_stringybark.flosf
node.0001_sc_stringybark.flobf
node.0001_sc_stringybark.floin
node.0002_ga_widebridge.dsflow

Run it

Save the file and hit Run in Kalix IDE. The simulation should finish in a fraction of a second.

screenshot — Run button & success message

Look at the output

The Run Manager opens to a chart view. Drag observed.csv in, then plot node.0002_ga_widebridge.dsflow against the obs column.

✓

Try plotting the three runoff components together: baseflow is the steady background, surface flow the spiky storm response, interflow sits in between.
