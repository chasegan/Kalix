- Input data checks (#479):
    - A CSV input with only one row of data, or none, now stops the run with an error naming the input, instead of crashing. Kalix needs two rows to work out the timestep.
    - So do inputs on different timesteps, and inputs that never all have data on the same timestep (e.g. an all-blank column, or date ranges that don't overlap).
    - A `start` after the `end`, or outside the input data, is refused with both dates named. The old messages said the opposite or blamed the data.
    - `kalix convert`, Python's `write_pixie()` and the IDE no longer stamp a timestep on a single row of data. The Pixie they write records no timestep, so running it is refused just as running a one-row CSV is.
    - A Pixie file holding an empty series can now be read back in the engine and the IDE; its `.pxt` used to hold an invalid start and end.
    - Python: `read_pixie()` returns an empty series as a column of NaN on the other series' timestamps. Series with values on different timesteps are still refused.
    - Python: `set_input()` now raises `ModelValidationError` for data with no rows or one row. Previously it assumed a daily timestep for a single row, and raised `ValueError` for no rows.
- IDE: files dragged from Finder or Explorer onto the project tree are copied into the folder they land on. If a name is already taken, you're asked to replace it or keep both (#469).
- IDE: New! Move a plotted series to a secondary Y axis (#196). Ctrl+click a series in the key (Cmd+click on macOS), or right-click it and choose **Move to secondary Y axis**, to plot it against its own axis on the right. The key groups series by axis, and the plot menu gains **Copy secondary Y axis**, **Paste secondary Y axis** and a secondary Y row in **Set axis limits**.
- IDE plots: drag an axis to set its range. The bottom or top half of a y axis moves its minimum or maximum, the left or right half of the time axis its start or end. Double-click an axis to fit just that axis.
- IDE plots: with **Auto-scale Y axis** on, an axis with no data in view now keeps its range, where it used to jump to -1 to 1.
