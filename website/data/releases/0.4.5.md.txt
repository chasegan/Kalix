- New data view (instead of map) when you open a data file!
    - The model map & new data view area now live inside each model's tab. This gives more horizontal space for tab names. 
    - The raw text visible in the text editor. 
    - Plot and data table appear on the right hand side.
    - Right-click `Find` menu allows searching by value or date.
    - Big files are openned as read-only (default threshold = 50MB, Preferences → Editor → Load and Save).
- New optional `forced_level` property for storage nodes allows modeller to force end-of-timestep level.
    - Output `adjustment_volume` indicates all changes to volume due to forcing, and `sid_flux` (storage inflow derivation) reports the adjustment volume on the interior of the supplied data.
    - NaNs are read as "not forced" for the timestep.
- New optional `loss_rate` property for loss nodes allows modeller to set loss rate using an expression (instead of the loss table). 
    - This will be valuable in representing antecedent losses.
    - The table still shapes upstream ordering.
- New support for `.csv.zip` file format!
    - The convention is one file per zip. 
    - This is a convention pandas reads and writes natively, is now a first-class data format in Kalix.
    — Reference .csv.zip files directly in the model, write them using `kalix simulate -o`, and use them throughout KalixIDE.
- New (ALPHA IMPLEMENTATION) dead storage and evap loss features in routing nodes:
    - `dead_storage` allows modeller to define a dead storage volume.
    - `loss_rate` property defines the loss in ML/step using an expression and is distributed equally across all reach divisions.
- New optional `order_factor` for regulated user nodes. This is a factor applied to the node's order as it is sent upstream. 
    - The node's own `order`, `order_due`, and account debits and delivery logic are unchanged.
- New `kalix convert` CLI command for data file conversions:
    - convert timeseries data files between known file types (e.g. `kalix convert flows.csv flows.pxt`).
    - matching `kalix.convert()` Python function.
- Plotting / run manager enhancements:
    - Every tab now carries plot & stats.
    - New seasonal mask filters data to chosen months of the year, using the calendar button in the plot toolbar.
    - Automatic data masking: selecting a plot type now applies that type's default overlapping-data mask. Badges in the plot-type dropdown show whether a mask will apply.
    - Plot undo/redo now restores source selection.
    - Plot tab `Reset` now preserves tab's name, position and undo history.
    - Run & data tree tick-boxes now stay in sync with the plot through tab reset, undo/redo, and tab duplication.
    - Plot source `[Last]` self-heals upon deleting the newest run, and re-points to the next most recent run.
- Minor fixes:
    - Comments: `#` starts a comment on any line, including after a section header (`[node.weir] # gauge site`) and after a `[data]` or `[outputs]` entry. Previously a comment after a header silently swallowed the node. `;` is not a comment character in Kalix — the linter now says so instead of letting the engine misread the line.
    - Hover tips in the editor no longer linger after you minimise the window or close the tab, and they follow the theme's colours.
    - Routing `pwl` tables accept a header row (`Flow [ML], Travel Time [steps]`).
    - Table View was previously not refreshing on optimiser's `Copy to Main Window` or after a file reload. Fixed.
- Performance:
    - Linting and the map re-parse are quicker on large models.
    - Results CSVs now use scientific notation for very small and very large values (e.g. `1.5e-7`). Precision is retained - but the files are now smaller.
