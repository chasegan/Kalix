- MAJOR FUNCTIONS UPGRADE!
    - Any expression can now be a program block `{ ... }` with local variables and `;`-terminated statements, where the final line is the value. Complex rules become readable, named steps instead of one long formula. Note that this means `;` is no longer used for comments (use `#` instead). 
    - User-defined functions: write a formula once in a `[fn]` section and call it as `fn.name(...)` from any expression. Inside a body, `this.` rebinds to the calling node.
    - User-defined variables: `[var.*]` blocks hold named calculations computed once per timestep at their position in the model file, readable from any expression and recordable in `[outputs]`.
    - User-defined lookup tables: define 1D and 2D tables in `[table.*]` sections and call them as `table.name(x)` or `table.name(x,y)` from any expression. Edit tables in the editor using Table View (`Ctrl+T`).
    - New functions: `moving_sum` / `moving_mean` / `moving_min` / `moving_max` over an n-step window, and `sum_since` / `min_since` / `max_since` / `count_since` / `steps_since` which accumulate until a reset condition.
    - New simulation flags `sim.new_day`, `sim.new_month` and `sim.new_year` mark calendar boundaries, making "start of the water year" a one-line condition (e.g. `sim.new_month && sim.month == 7`).
    - New `assert()` function you can use to guard your model's assumptions. If a condition is zero (or NaN) the run halts immediately and tells you which statement failed, at which timestep, at which node.
    - New `clamp(x, lo, hi)` builtin.
    - Renamed `avg()` to `mean()` (breaking change).
    - Linter support for program blocks, `[fn]`, `[var.*]` and `[table.*]` sections as you type, and autocomplete offers the new functions, `fn.` / `var.` / `table.` references, and section headers.
    - All the above is [documented here](https://kalixproject.org/docs/dynamic-expressions/).
- Routing params exposed to the optimiser: `pwl_tt_<i>` (for PWL) and `nlm_k` and `nlm_m` (for NLM).
- Storage node `exists` parameter.
- New `Insert node` templates from the editor's context menu, or from the map context menu.
- The Run Manager's outputs tree now uses checkboxes so that selection is maintained while user interacts with the tree.
