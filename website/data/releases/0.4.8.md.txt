- New! Give your nodes descriptive display names using [annotations](https://kalix.org/docs/conventions/#annotations):
    - Kalix annotations are special comments that start with "#@". They are still treated as comments by the engine, but they have special powers in the IDE.
    - Kalix's first annotation, `aka`, allows you to assign alternative names just for the node diagram, e.g. `#@aka = Teemburra Dam (147,500 ML)`.
    - Click the node-label button in the IDE to cycle between label modes: formal names, akas only, hidden.
- Improved account behaviour for [regulated users](https://kalix.org/docs/regulated-user/#accounts) with travel time:
    - Each account maintains a record of committed water, i.e. orders placed against the account but not yet diverted.
    - Regulated user orders are limited by the forecasted account balance (current balance minus commitments).
    - Regulated user diversions are limited by the actual account balance.
    - New account output: `acc.<name>.committed`, also on group aggregates.
- [`Sacramento` node](https://kalix.org/docs/sacramento/) features:
    - Soil moisture store outputs now recordable: `uztw`, `uzfw`, `lztw`, `lzfp` and `lzfs` in mm.
    - Sacramento calibration now defaults to ratios `lzpkonlzsk` (`lzpk / lzsk`) and `sarvaonpctim` (`sarva / pctim`) rather than `lzpk` and `sarva`. See [optimisable parameters](https://kalix.org/docs/optimisable-parameters/#the-ratios-lzpkonlzsk-and-sarvaonpctim).
    - Existing optimisation configs that target `lzpk` and `sarva` run unchanged.
- New map candy! 
    - `Select nodes` in the schematic map's context menu gives several options: all, upstream, downstream, or connected.
- [`Field` node](https://kalix.org/docs/field/) improvements: 
    - New! `crop_N_kc_multiplier` on the `field` node scales the crop coefficient dynamically, supporting simulation of skip-row irrigation practices.
    - `soil_moisture_vol` output renamed `volume` for consistency with other nodes.
- Timestamp changes:
    - Output CSV files now head their first column `date`, or `datetime` when the timestamps carry a time of day (hourly data, or daily data stamped at 9am), rather than `Time`. Postprocessing tools that look for a `date` column now find it; scripts that select `Time` by name need updating. The IDE's plot `Save Data` export does the same (previously `Datetime`), and heads an exceedance export `percentile`. The Python package names its DataFrame index by the same rule (previously `time`).
    - Daily models stamped at a time (other than midnight, e.g. 9am) now retain the same time component in the model output.
    - New checks to ensure that all [input data shares the same time of day](https://kalix.org/docs/input-data/).
    - `start` and `end` must also fall on the data's timesteps, e.g. `start = 2020-01-02T09:00:00` for 9am data.
- Minor bug fix:
    - Cursor position after change of screen scaling factor (#162).
