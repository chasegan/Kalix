- Website: every link and button shows the same keyboard focus ring; tutorial and docs screenshots are framed with captions and a zoom badge; the About Kalix page is rebuilt and its quick example runs again; the Ask panel has a close button (Esc closes it too).
- Storage ordering targets (#492):
    - `target_volume` sets an ordering target as a volume [ML], as an alternative to `target_level`. The two cannot be given together, and both `target_level` and `target_volume` results are available whichever is used.
    - `forecast_volume_adjustment` [ML] adds the net water you expect to arrive (+) or leave (-) before today's order does, such as a forecast inflow or a planned diversion, to the forecast a target storage orders against. It is a total over the order travel time, not a daily rate, and is added on top of the orders already en route. It needs a target.
    - A new `forecast_volume` result records the forecast each target order is based on.
    - The IDE linter flags both targets given together and an adjustment without a target, and warns that a target has no effect under `order_through = true`.
- `true` and `false` are read in any case (`TRUE`, `True`) for `order_through`, `demand_carryover` and a table's `bilinear`, in the engine and the IDE linter alike. Before, the engine refused anything but lowercase (#522).
- Var blocks (#493):
    - `[var.*]` blocks can take `phase = order`. The block runs at its place in the order phase, which works up the file: it reads the orders of nodes below it, and nodes above it read the block in their order inputs (an order control's `set_order`, a storage's `target_level`).
    - A node or var above a `[var.*]` block can now refer to it (e.g. at `[-1, 0]`). This used to fail at load as a duplicate var definition.
    - An error while running a var block now names the block, not the last node run, and one in a `[ras.*]` section names the section.
