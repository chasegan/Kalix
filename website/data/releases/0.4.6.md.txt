- New rainfall-runoff nodes: [AWBM](https://kalix.org/docs/awbm/) (`type = awbm`) and [SURM](https://kalix.org/docs/surm/) (`type = surm`).
    - AWBM is the Australian Water Balance Model with its 8 standard parameters. `variant = two_tap` selects Hydro Tasmania's AWBM Two Tap (11 parameters), and the optional `cap_ave` expression scales the three surface-store capacities each step, so a seasonal capacity profile can be a table lookup on `sim.day_of_year`.
    - SURM is the Simple Urban Runoff Model used by MUSIC and Source, with runoff generated separately from the impervious and pervious parts of the catchment.
    - Both are drawn as water drops on the map, open in the context-menu table view for `params` and station-weighted `rain`, and have default optimiser expressions and documented search ranges. The `rf_bias` / `rf_di` rainfall-input parameters apply to them as to GR4J and Sacramento.
- New [field](https://kalix.org/docs/field/) node (`type = field`): an irrigated field with a root-zone soil store.
    - The soil runs the FAO-56 daily root-zone depletion balance with a crop coefficient and a stress coefficient. Rain fills the soil first, then irrigation takes from what arrives, no more than the soil has room for, allowing for application efficiency.
    - A field orders water upstream to meet its deficit, with an `order` expression that reads its own end-of-step states from the previous step: `this.depletion[-1, 0]` and `this.orders_en_route[-1, 0]`.
    - Its `ds_1` carries surplus and returns back to the river. The links leaving a field are drains, not delivery paths, so they are not regulated and add nothing to travel times downstream.
- New supply outlets (`ds_2` to `ds_4`) on regulated and unregulated user nodes, so a user can supply other nodes such as fields through its own pump and accounts.
    - The node on a supply outlet places its orders with the user. A regulated user adds them to its own order and holds each for its travel time; an unregulated user starts a regulated zone of its own and releases at once.
    - Supply outlets are served first when the take is short, and everything that limits or meters the take (`pump`, `flow_threshold`, `annual_cap`, account balances and debits) applies to the whole diversion. New outputs `ds_N`, `ds_N_order` and `ds_N_order_due` per outlet.
- Splitter nodes now deliver regulated orders down the effluent.
    - An order placed on `ds_2` is held for the travel time from the supply and sent down the effluent when the water arrives (new `ds_2_order_due` output).
    - The order sent upstream is raised to cover what the table diverts at regulated flows, as it is through a loss node, and the main-channel order is held to what the table can pass.
    - The `table` is now optional. A splitter with no table diverts nothing of its own accord and sends down `ds_2` exactly what is ordered, which represents a regulated offtake such as the head of an irrigation channel.
- New `allocation_pct` output for accounts and account groups: allocation as a percentage of size (100 = full entitlement; can exceed 100).
    - `acc.<account>.allocation_pct` for each account, and `acc.<group>.allocation_pct` for the group as a whole (total allocation over total size).
    - Reports the allocation actually held, which can differ from the percentage an `allocate` action announced (`ras.<name>.pct`).
    - Reads `NaN` for a zero-size account or group.
- New storage outputs `order` and `orders_en_route`: the order a storage places upstream to reach its `target_level` (or passes on with `order_through`), and the water on its way to it at the end of the step. Not written for a storage that does not order.
- Ordering refinements:
    - A node may have any number of incoming regulated links. A third one previously stopped the run at step 1. A confluence still directs orders up two branches at most, and now reports an error at initialisation for more.
    - A storage or order control below branches of different travel time is now timed from the longest regulated branch, as documented, rather than the branch defined last.
    - Below a confluence that names its `regulated` pathway(s), the travel time comes from the named branches alone, since those are the only branches an order can travel up.
    - A confluence on a regulated pathway with neither `regulated` nor `harmony_fraction` now sends no orders upstream, so the missing pathway shows in the results. Previously every order went up the branch defined second. Such a model should say `harmony_fraction = 0`.
    - A regulated user whose `order` expression evaluates below zero now orders nothing, with or without accounts. Previously, with accounts, the negative order went upstream and reduced what the network saw from the nodes below.
    - A supply storage with no incoming regulated link is now visited in definition order like every other node, so an expression such as `node.dam.ds_1_order` can read it in the same step.
    - A confluence's recorded `harmony_fraction` now reports the value on the step it was used, rather than one step behind.
- Large Pixie (`.pxt`) results files no longer run KalixIDE out of memory.
    - The Run Manager opens a Pixie file straight away and only reads the series you tick. Ticking more than fits in memory at once is refused with a message.
    - The data viewer and FlowViz still load a whole file, so a file too big for memory is refused with a message pointing you to the Run Manager (hover the message to read it in full).
    - If a loaded file changes on disk, plotting from it shows an error; remove and re-add it to pick up the new data.
- Draw links on the map: drag out from just beside a node and drop on the downstream node. The link uses the first free `ds_N`, or re-points the last allowed outlet when all are used. Self-links, duplicates and loops are refused; Esc cancels and Ctrl+Z undoes.
- Run Manager timeseries tree context menu:
    - New "Show checked" and "Show selected" commands fold the tree back to just the ticked or selected series and their parents.
    - Right-click now works anywhere along the row, not just on the label. Right-clicking below the last row clears the selection and acts on the whole tree.
    - "Collapse all" with nothing selected no longer hides every row; it folds back to the top-level runs and datasets.
    - Menu items that cannot apply are hidden or greyed, such as "Show checked" with nothing ticked.
- Minor fixes:
    - Running the same model object twice, as the optimiser does on every evaluation, no longer starts from the previous run's state: a regulated user's pending orders and a RAS's standing `pct` announcement are reset at the start of each run. Optimiser evaluations after the first could previously see stale orders fall due on the first steps.
    - With a filter on the Run Manager's outputs tree, checking or unchecking a run, or re-running with the filter on, no longer empties the plot of the series the filter hides.
    - The IDE now reads and writes proleptic year 0000, so the Pixie output of stochastic engine runs spanning 0000-01-01 to 9999-12-31 opens in the data viewer and Run Manager.
    - The editor tab right-click menu was not reliably shown. Some platform popup gestures were missed, and the menu was suppressed for a file outside the open project folder.
- Performance:
    - Splitter and loss nodes skip their table lookups where the table diverts or loses nothing, in both the flow and order phases. A splitter with no table, or a high-flow breakout running beneath its threshold, is up to a third cheaper per step.
