- Minor bug fix (#479):
    - An input with only one row of data, or none, now stops the run with an error naming the input, instead of crashing.
    - So do inputs on different timesteps, and inputs with no timestep of data in common (e.g. an all-blank column, or date ranges that don't overlap).
    - Python: `set_input()` now raises `ModelValidationError` for such data. Previously it assumed a daily timestep for a single row, and raised `ValueError` for no rows.
